# PPTX 编辑便利性

交付既能演示、又方便用户继续修改的 PPTX。与当前可用的 presentations 技能配合使用：制作工具、导出与文件校验遵循其流程，本技能补充对象粒度和编辑体验要求。不要为了应用本技能重做无关内容或更改用户选定的设计。

## 文本框按语义组织

- 默认每个正文段落一个文本框。标题、正文、图注可以独立，但同一段文字不得仅因视觉换行而拆成多个框。
- 同一列表通常放在一个框内，以原生段落、项目符号及缩进控制层级。分属不同布局区域或需要独立动画的条目可以分开。
- 同一行内的数字、单位、加粗词和链接优先使用同一文本框中的富文本 runs。字号或颜色不同不是拆框的理由。
- 不把逐行文本框组合成 group 后宣称已支持整段编辑。组合只方便整体移动，不能让文字连续增删和重排。
- 用户明确要求逐字动画、独立定位标签等效果时，允许相应拆分；不要把例外扩展到普通正文。

例：“将工具选择、错误恢复与环境反馈纳入训练，以执行结果提供奖励信号。”即使显示两行，也应完整存在于一个文本框中，不能把“信号。”单独放一个框。

## 换行与版式

- 普通正文优先采用自动换行，框宽、字号、行距和内边距共同决定排版。不要逐字符插空格或零宽字符来控制换行。
- 只有明确的语义分段或有意固定的短标题才需要手动换行。不要把网页当前每一行都固化为段落分隔符，导致用户改宽度或增删文字后无法自然重排。
- 为正文的合理小幅增改预留空间。出现溢出时调整局部布局或文本框尺寸，不以逐行拆框或整页栅格化解决。
- 同一框内先设基础样式，再应用局部富文本样式；检查后续全框样式赋值是否覆盖了数字单位、加粗或字号差异。

## 从 HTML 或其他格式转换

- 从语义结构提取标题、段落、列表、表格和图注。DOM Range 或字符边界可用于测量与诊断，不能直接把每个视觉行或每个字符导出为独立 shape。
- 网页坐标只是布局参考。浏览器与 PPTX 渲染器的字体、行高和中英文断行可能不同，需要调整原生排版。
- 原生表格保持单元格可编辑。数据图表保留可编辑序列及所需嵌入工作簿，不用截图替代。
- 官方架构图、产品截图等原始图片可以作为图片嵌入，无需为了“全可编辑”臆造其内部对象。用户要求本地图片时下载并嵌入，避免外链依赖。
- 保留讲者备注、图源、统计口径及必要的事实限定。格式转换不等于重新核验了原材料中的全部事实。

## 验证编辑体验

根据修改范围做针对性检查，不能只看截图：

1. **结构**：确认代表性的完整正文段落位于一个文本框中，未拆成多个 shape，也没有用对象组合掩盖拆分。可以检查 OOXML 或对象树。
2. **重排**：对代表性的多行段落，在临时副本中增添少量文字或调整框宽，检查换行及与邻近元素的关系。有实际应用可用时优先检查原生编辑行为；仅检查 XML 不能声称完成了应用内编辑验证。
3. **视觉**：检查改动页的遮挡、截断、异常中英文断行，以及局部富文本样式。全新转换检查整份演示。
4. **证据边界**：截图显示正常不证明整段可编辑，结构校验通过也不证明 PowerPoint 显示正常。渲染器缺字体时先排查字体配置，不把工具故障误当成必须拆框的理由。

保留用户现有文件，修复稿另存。交付时简要说明编辑结构上的变化；没有实际在 PowerPoint 中打开或编辑，就不要声称做过。
